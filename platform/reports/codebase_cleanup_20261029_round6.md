# 全库代码审查与精简：第六轮（2026-10-29）

本轮继续按本地单用户研究与每日运行规模检查数据抓取、ES 参数和稳健性工具。前轮记录见[第五轮](codebase_cleanup_20261029_round5.md)。本轮没有访问真实行情接口，也没有运行真实研究或账户操作。

## 已修复的问题

1. **同一中债数据源有两套实现，独立入口在 WSL 下会记错日期**（`fetch_chinabond_30y.py`、`sync_index_benchmark_data.py`）
   - 独立入口用本机时区转换官方毫秒时间戳，WSL 的 UTC 环境可能把中国交易日写成前一天；还可用较旧快照覆盖较新历史。
   - 删除独立的抓取与行情组装副本，两个 CLI 共用中国时区解析、行情规范化和官方窗口合并；旧快照、坏价格、已有文件的坏日期在写盘前拒绝。修正独立入口切换目录前没有保存调用目录的问题。
   - 官方窗口内的权威替换语义保留。新增独立 CLI 回归确认拒绝旧快照且原文件字节不变；零、负数和无穷指数点位均被拒绝。快照中只有部分记录损坏时也整批拒绝，避免过滤坏行后在窗口内删除历史。

2. **稳健性诊断使用另一套复权逻辑，且没有当前行情门禁**（`analyze_es_robustness.py`）
   - 旧 `adjusted_close` 只按行情日映射因子，可能漏掉第一条行情之前已生效的因子；指数与 ETF 又被强制从 ETF 配置的数据目录读取。预算归一化也有重复的大数溢出路径。
   - 删除该价格副本及闲置参数，复用 `LocalCsvBarData`、资产与策略配置验证、共享预算归一化。两份配置分别读取自己的目录，先检查行情新鲜度与代理之间的末日对齐，再计算诊断。
   - 零或非有限总风险不再变成全 NaN 后被 `nansum` 报成“预算误差为零”；Bootstrap 少于两次成功时报告失败次数并停止，避免空矩阵索引崩溃或伪区间。无下跌样本时，下跌相关性明确为空值。

3. **诊断矩阵与结果可以覆盖旧文件，置信水平没有传给生成配置**
   - 分析输出改为独占新目录；配置按本次微秒时间戳写入独立子目录，使用独占文件创建。生成器删除未使用的 `config_path` 参数。
   - CLI 置信水平现在进入生成配置，诊断与后续运行不会无声地采用两组置信水平；窗口、方法和 Bootstrap 参数在计算前检查。
   - 回归确认重复生成拒绝覆盖、原 YAML 不变，以及自定义 90% 置信水平正确进入配置。

4. **汇总工具改算旧收益、暗中截短样本，并在合法空结果上崩溃**（`summarize_es_robustness.py`）
   - 绩效现在优先读取产物中的 `metrics.json`，否则读取 manifest 已保存的 `metrics`；删除重算绩效的调用。回归用不同的已存指标证明优先级，没有从当前代码重建旧收益。
   - 去掉固定的 `2023-06-13` 起点筛选，改为可选 `--start-date`。敏感性目录移动或从 Windows 转到 WSL 后，优先使用 manifest 同目录的 `sensitivity_summary.csv`，并正确解析 Windows 配置文件名；缺失必需文件会报错，不再静默漏算。
   - 无交易、空 CSV、单一方法或单一代理均能输出适当空表，不再因分组或透视列缺失崩溃。未知代理/矩阵身份明确失败，避免误贴 ETF 标签。
   - 输出目录必须新建，权重诊断改为显式 `--diagnostics-csv`，删除从父目录猜输入的隐含约定。
   - `theoretical_*` 仍是用当前数据与当前无约束 ES 代码计算的参考，新增 `theoretical_basis` 并在文档说明；没有把它宣称为历史策略当时的完整目标。

5. **冷却期的上限向量与趋势名单错位，部分非法 ES 配置被忽略**（`strategies/expected_shortfall.py`）
   - 权重边界统一按完整声明的资产顺序验证，再选择活动资产；字典与向量共用解析流程。冷却移除 A 后，B/C 的向量上限不再维度报错或错位。
   - 趋势资产名单按完整配置验证，冷却中的合法资产不会被误认为未知代码。
   - 拒绝边界的错误类型、未知键、非有限值及越界值；负/NaN 集中度惩罚和波动目标不再静默停用。要求 `2 <= min_periods <= rolling_window`，避免一个永远达不到最小样本的配置持续无操作。
   - 回归验证冷却后的真实求解权重为 B 80%、C 20%，以及非法选项明确失败。

6. **NAV 分页可能假完整，数值过滤和覆盖保护仍会丢历史，报告使用未披露值**（`fetch_etf_nav.py`）
   - 要求 `TotalCount` 有效且在分页期间稳定，抓取行数严格匹配；重复日期不能借行数达到“完整”。HTTP 错误、分页截断、缺失总数、日期异常和非有限/非正单位或累计净值全部拒绝入库，不再丢掉坏行后继续报告成功。
   - 原来的“行数与末日不倒退”不能识别中间历史丢失；现在要求新结果覆盖全部已有日期。即使新结果更长、末日更新，也不能删掉本地旧观测。
   - 配置只选择 ETF，避免向基金净值接口发送指数代码。合并重复异常分支，写盘或报告失败都会进入失败清单。
   - `--report` 先经行情门禁，再通过 `EtfPremiumStore.observable_history` 扣除发布滞后，标出截至日和实际观测日；删除原始同日价格/NAV 比值的报告副本。滞后后历史不足时明确报告失败，已成功同步的 NAV 仍保留。
