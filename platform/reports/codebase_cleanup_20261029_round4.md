# 全库代码审查与精简：第四轮（2026-10-29）

本轮按本地单用户研究、每日模拟和持仓镜像的使用规模继续检查。先完成版本、配置和指数语义修复；用户要求优先处理 C 盘空间后，先释放空间，再继续归因和数值算法审查。前轮记录见[第三轮](codebase_cleanup_20261029_round3.md)。

## 必须修复：本轮已落实

1. **实际执行策略与记录的版本可能不一致**（`engine.py`、`sim.py`、`storage.py`、`live.py`）
   - 用途：给运行、checkpoint 和恢复状态记录正确身份。
   - 问题：配置提供现存 ID 时，只检查 ID 存在，仍执行当前注册类，能把另一个策略或另一组参数的版本贴到本次结果上；父类变化也不会改变原来的类源码哈希。
   - 修复：总是按实际类、父类定义和参数登记版本，删除两处重复的旧 ID 回退分支；模拟和实盘 runtime 复用也要求源码哈希一致，旧状态保留已有持仓的启动兼容行为。
   - 不修复的后果：结果身份失真，代码更新后可能复用不匹配的运行状态。六个旧 ID/父类回归在修复前失败，修复后通过；另验证了 runtime 不会跨缺少来源证明的快照恢复。

2. **资产与策略配置错误会静默改变投资组合**（`models.py`、`data_store.py`、`engine.py`）
   - 用途：构建资产池和策略输入。
   - 问题：重复 `asset_id` 被字典覆盖，同一代码可被重复计入；零/负手数被替换，小数手数被截断；重复 universe 会制造非预期现金仓位，非映射 params 则在深层调用才崩溃。
   - 修复：在共享入口拒绝重复身份/代码、非法手数、非法 params 和重复或非列表 universe；资产涨跌幅参数同时校验范围。
   - 不修复的后果：拼写或配置错误被误当成一组有效参数。151 份固定配置的资产、策略注册和执行参数均已验证通过，没有修改固定策略配置来绕过检查。

3. **非法执行参数会产生错误成交或资金结果**（`execution.py`）
   - 用途：选择成交价格、交易顺序、取整与滑点。
   - 问题：`price_field=volume` 可把成交量当价格，拼错取整模式默默回退；非有限现金缓冲/容差被接受，超过 100% 的卖出滑点可产生负价。
   - 修复：统一校验模式选择、有限比例、滑点及参与率参数；要求最大可能滑点仍保留正的卖出价。
   - 不修复的后果：错误配置进入成交环路，污染现金、成交与报告；现在在创建执行配置时就失败。

4. **初始持仓绕过已有状态校验**（`engine.py`）
   - 用途：按配置启动已有持仓的回测。
   - 问题：先创建空状态，再逐个改写持仓字段，因此新加的状态构造校验看不到负数量、非有限数量或非法成本；重复初始持仓又按最后一条覆盖。
   - 修复：先构造并检查持仓映射，再创建状态；重复初始持仓明确报错。
   - 不修复的后果：初始化和 checkpoint 恢复采用不同准入规则。五个回归确认错误在写运行目录前停止。

5. **发布指数沿用了 ETF 默认手数和涨跌停，报告未明确研究性质**（平台资产加载、ETF 配置生成和报告）
   - 用途：支持指数作为不可直接交易的研究基准。
   - 问题：缺省参数的指数被设为 100 份一手、10% 涨跌幅；显式 `price_limit_pct: null` 又会因 `float(None)` 崩溃，含指数篮子也缺少清楚标签。
   - 修复：缺省非 ETF 采用 1 单位、无涨跌停，保留显式 null。新回测 manifest 和报告记录不可交易指数；ETF 排名、篮子和生成元数据标明含指数的研究模拟。
   - 不修复的后果：研究模拟受错误的 ETF 约束影响，或被误读为可执行组合。合成指数在无成交量、单日上涨 20% 的输入下正确进行虚拟交易，并明确标注研究模拟。

6. **缺一个单位净值就可能把入金算成投资收益**（`attribution.py`、`platform_dashboard/artifacts.py`、`app.py`）
   - 用途：按收益口径展示账户与影子模型的表现。
   - 问题：月度归因对空单位净值逐行回退到账户金额；看板只要一行单位净值缺失，就把整段历史回退到账户金额。此外月报把单位净值的 1 → 1.01 标成账户“总值”。
   - 修复：有单位净值列就不改用金额；归因拒绝无效净值，看板略过无效行并显示质量提示。归因收益使用净值，账户总值字段使用实际账户金额；无该列的旧档案仍保持旧口径。
   - 不修复的后果：申赎污染收益，或无效模型净值触发除零/非有限结果。回归分别验证入金、缺失行、零/无穷模型净值和真实金额展示。

7. **另两个报告入口仍可覆盖已有文件**（月度归因 CLI、HFQ 校验输出）
   - 用途：保留月度记录和数据校验依据。
   - 问题：重复运行按同一路径覆盖月报；HFQ 校验目录也允许复用，秒级默认路径还可能碰撞。
   - 修复：月报使用独占文件创建；HFQ 校验拒绝复用输出目录，默认时间戳增加微秒。
   - 不修复的后果：旧报告在重跑时消失。回归用实际子进程重复生成月报，验证第二次失败且原文件字节不变。

8. **约束 ES 的最后归一化破坏了配置下限**（`strategies/expected_shortfall.py`）
   - 用途：同时满足预算、上下限与权重和为 1。
   - 问题：下限为 40% 的资产，在旧投影路径中会降到 28.57%；矛盾上下限又被 `clip` 静默改写，非法维度或非有限边界到求解内部才暴露。
   - 修复：求解前验证边界和可行性；初始点、常规结果和二分回退结果共用有上下限的单纯形投影。删除两套剪裁/归一化补丁，允许声明的零下限，不再通过最后除以权重和破坏边界。
   - 不修复的后果：看似成功的求解结果违反用户配置。回归复现旧 28.57% 结果，并验证修复后同时满足上下限和满仓约束。

9. **PCA 等价符号变化能把平滑后的因子抵消为零**（`strategies/macro_factor_es.py`）
   - 用途：跨期平滑主成分暴露。
   - 问题：同一分解的正负号等价，但直接做 EWMA；当 `lambda_beta=0.5` 且符号反转时，全部暴露被抵消。SVD 失败时还改用人工全 1 矩阵继续计算。
   - 修复：平滑前按前一期方向对齐每个因子的符号；删除合成矩阵和吞异常分支，让分解失败明确停止。
   - 不修复的后果：纯数值表示变化被当成风险结构变化，或者分解失败仍产出貌似有效的权重。两个回归在修复前均失败，修复后通过。

## C 盘空间处理与后续约束

- 开始时 C 盘可用 **1.52 GB**，D 盘可用约 31 GB。
- 识别出诊断日志约 2.5 GB、崩溃转储约 0.49 GB，以及可再生成的包缓存。没有读取凭据、聊天内容或真实账户文件。
- 原计划递归清理缓存的命令被自动审批拒绝，原始原因仅为 `blocked by policy`；没有把删除操作换一种命令重试，也没有宣称缓存已删除。
- 在线执行 WSL `fstrim`，没有把其显示的逻辑 trim 容量当作 C 盘实际释放量；C 盘空间没有明显变化，未关闭 WSL。
- 改用可逆的 [Windows NTFS 压缩](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/compact)，保留诊断日志与崩溃转储的文件内容。诊断日志从 2,698,522,624 字节占用压到 192,434,176 字节；崩溃转储从 525,111,051 压到 162,603,008 字节。
- 观察到 C 盘可用空间提高到约 **4.18 GB**，实际释放约 **2.6 GB**。后续快照约 4.1 GB，仍需避免大型缓存继续写入 C 盘。
- 本任务后续临时数据使用 `D:\codex-cache\strategy-audit\tmp`；安装/下载工具时优先把 `UV_CACHE_DIR` 放到 D 盘。没有修改全局环境变量或系统注册表。
- WSL 的 `/tmp` 为内存文件系统；显式将 `TMPDIR` 指向 D 盘后，pytest 默认文件描述符捕获遇到 DrvFS 兼容问题。改用 `--capture=sys` 后通过，测试数据仍保留在 D 盘；没有把运行前的捕获错误算成测试失败或测试通过。
