# 全库代码审查与精简：第三轮（2026-10-29）

后续修复与 C 盘空间处理见[第四轮](codebase_cleanup_20261029_round4.md)；本记录保留第三轮结束时的状态和验证计数。

仓库用于本地量化研究、日频模拟、真实持仓镜像和 ETF 筛选。本轮按单用户脚本及每日任务的使用规模检查，重点追踪结果来源、决策数据、缓存、持仓恢复、企业行为和通知。以下问题均已落实修复；全库审查继续进行，不把测试通过等同于策略数学、真实供应商或真实账户已全部验证。

前轮记录：[第二轮](codebase_cleanup_20261029_round2.md)、[第一轮](codebase_cleanup_20261029.md)。

## 必须修复：本轮已落实

1. **截短回测写进正式目录，旧产物缺来源仍进入默认看板**（`engine.py`、`run_platform_backtest.py`、`platform_dashboard/artifacts.py`）
   - 用途：正式目录只保存固定配置的完整共同历史。
   - 问题：目录取自 YAML，运行时截短日期后仍沿用 `results/backtests/`，无法证明正式结果的来源。
   - 修复：CLI 传入配置来源；引擎对照固定 YAML、运行时日期和滑点场景，并用完整原始行情计算共同首尾日期。无法证明的运行自动分流到临时直接回测目录，manifest 记录 `artifact_provenance`。缺少证明的旧产物通过看板“包含临时回测”选项查看，历史文件不搬迁、不重写。
   - 不修复的后果：临时结果混入默认正式列表。本轮用固定、生成、截短、无来源、参数变动、配置自带日期及不等长历史等输入验证。

2. **进程全局缓存跨运行复用旧溢价与旧估值**（`etf_premium.py`、`index_valuation.py` 及策略调用方）
   - 用途：同一次回测内缓存小型时间序列，避免逐日重复读盘。
   - 问题：按目录保存全局实例，文件更新后同进程后续策略仍读旧数据。
   - 修复：由每次策略初始化持有自己的仓库实例，保留单次运行缓存；删除两个全局缓存、两个工厂和两个测试重置函数。回归在同一目录更新数据后启动第二次策略，确认选择随新数据变化。
   - 不修复的后果：数据同步成功后，下一次研究仍可能使用旧信号。

3. **QDII 筛选绕过发布滞后，缺数据时编造溢价与成本**（`etf_selection/src/selection.py`、`etf_premium.py`）
   - 用途：比较 QDII 袖子的可观测溢价、流动性及披露费率。
   - 问题：直接使用同日价格/净值；数据缺失时填入 `premium_std=0.02`，又把年费率当持有成本。加载层还允许把发布滞后设成零。
   - 修复：统一经过 `observable_history()` 的最少两个交易日保护；独立 ETF 工具通过 `read_etf_premium.py` 的 JSON CLI 读取，不导入平台内部代码。缺净值、累计净值或明确费率则拒绝候选。删除未经支持的实际持有成本估计，使用名称明确的 `expense_ratio`；当前 ETF 配置的评分字段同步更名。
   - 不修复的后果：尚未公布的数据影响筛选，缺数据的候选凭虚构数字参与排名。端到端测试通过真实子进程验证未披露尾部数据不会进入输入。

4. **QDII 结论没有展示两种收益口径及端点溢价**（ETF 报告）
   - 用途：辨别场内价格表现与净值表现之间的差异。
   - 问题：旧报告只展示评分、所谓成本和溢价标准差。
   - 修复：报告在同一个已可观测配对区间展示复权市场价年化、累计净值年化、起止溢价、观测截止日期及披露年费率。说明短样本年化仅作描述，费率不代表实际持有成本。
   - 不修复的后果：价格中的溢价变化可能被误读为标的收益。没有执行实际市场筛选或生成研究推荐。

5. **配置删去持仓资产后，恢复状态可能把它按零估值**（`models.py`、`sim.py`、`live.py`、`engine.py`）
   - 用途：恢复既有组合和 checkpoint。
   - 问题：持仓或待执行意图引用配置之外资产时，没有恢复校验；缺价格用零补齐，资产价值会静默消失。
   - 修复：在恢复与开始运行时校验非零持仓和待执行资产；非零持仓缺少有限正价时明确失败。状态加载同时拒绝非有限现金、非法数量/成本、无效目标权重及键与资产 ID 不一致。
   - 不修复的后果：配置变更或损坏状态污染净值。回归确认失败前不建立新的模拟状态、不改写原文件。

6. **创建模拟组合可覆盖同名组合，研究目录也可能同秒覆盖**（`sim.py`、实验/敏感性/ETF 入口）
   - 用途：增量续跑并保留原始产物。
   - 问题：模拟创建允许复用已有目录；实验、敏感性和 ETF 报告只有秒级时间戳，并以 `exist_ok=True` 打开既有目录。
   - 修复：新组合创建用独占目录；已有组合继续使用 load。研究时间戳加入微秒、目录冲突明确失败；ETF 生成 YAML 与报告也拒绝覆盖原文件/目录。
   - 不修复的后果：重复运行可能回退组合或覆盖已完成报告。模拟状态、生成 YAML 和报告覆盖保护均有文件内容回归。

7. **异常 Markdown 可让通知渲染死循环，发送错误还可能泄露请求密钥**（`notify.py`）
   - 用途：将日报和下单票转成 HTML 并发送。
   - 问题：单独的 `#`、未构成表格的 `|` 行进入普通段落后，索引不前进。发送失败使用完整异常堆栈，其中 HTTP 地址可能包含 SendKey。
   - 修复：普通段落先消费当前行，保证解析前进；发送错误只记渠道与异常类型。显式空渠道列表关闭自动发现，非法环境端口也返回失败而不中断主流程。
   - 不修复的后果：每日任务卡死、日志暴露请求地址，或者“关闭通知”后仍自动发现渠道。死循环回归放在有超时的子进程中；通知测试全部使用模拟发送，没有对外发消息。

8. **首次企业行为导入绕过重复检查，拆分校验依赖输入顺序**（`corporate_actions.py`、`fetch_etf_dividends.py`）
   - 用途：保留已有事件、审核候选新增，再更新事件表。
   - 问题：三个“没有已有记录”的分支各自直接接受候选；重复事件可进入初始表。拆分前后价格又按 CSV 行序选取，并只支持 `close`。
   - 修复：所有初始/增量路径经过同一个合并函数；统一先拒绝重复键，首次返回尚未接受的候选。删除三处重复分支与无实际用途的函数注入参数。拆分价格先排序，兼容 `close_price`，拒绝非正或非有限比例与价格。
   - 不修复的后果：重复分红可能重复计息，乱序行情可能错误接受或拒绝拆分。

9. **首日涨跌停失去前收，稀疏因子漏掉已知历史**（`data.py`、ETF 价格加载、`data_validation.py`）
   - 用途：按可用历史形成价格和交易限制。
   - 问题：行情先截短，再计算前收，导致首日涨跌停为空；因子仅按完全同日匹配，行情起点之前已有因子仍被当成 1。ETF 加载也存在乱序前填的问题。
   - 修复：先计算限制，再裁剪运行窗口；按不晚于行情日的最近因子配对，不借未来因子。ETF 与旧数据对照路径同步修复；拒绝缺日期、重复日期或格式损坏的因子文件。
   - 不修复的后果：边界订单错误成交，复权价格和交叉核验失真。测试验证截短首日涨停仍拒单，以及首条行情前因子为 2 时不会退回 1。

10. **已有 HFQ 文件损坏时，错误回退会重建并覆盖历史**（`hfq_factors.py`）
    - 用途：保留既有因子，只为新行情延伸。
    - 问题：缺列、坏日期或读取异常被吞掉，转入“没有旧文件”分支；重复日期、零与无穷因子也能继续传播。
    - 修复：删除回退分支，在任何写入前校验既有列、日期唯一性及有限正因子。错误时停止，原文件保持字节不变。
    - 不修复的后果：一次异常文件可能触发历史因子重置。五种损坏输入在修复前均未报错，修复后全部拒绝并保留原文件。

11. **没有有效净值基准时，回测在写报告阶段崩溃**（`engine.py`、回测 CLI）
    - 用途：展示回测指标与运行结果。
    - 问题：对 `total_return=None` 直接乘 100；零资产账户能触发此情况。
    - 修复：无基准时报告明确未知，CLI 显示 `N/A`；报告成交价说明也改为实际配置字段，删除过时的“默认中间价”描述。
    - 不修复的后果：原始文件已产生后，命令却在汇总时失败。
