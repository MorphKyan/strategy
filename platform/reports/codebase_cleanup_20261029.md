# 全库代码审查与精简记录（2026-10-29，持续进行）

后续修复与当前待办见 [第二轮审查记录](codebase_cleanup_20261029_round2.md)。下文保留第一轮的验证记录。

## 范围与使用场景

仓库负责日频回测、模拟组合、实盘镜像、ETF 筛选和本地只读看板。按单用户本地脚本、每日定时任务及少量同时运行的进程评估；没有按多租户在线交易系统扩建架构。

已扫描 60 个业务 Python 文件的定义和引用，检查命令行入口、配置、调用方与现有测试，重点追踪资金状态、订单意图、分红、文件持久化、行情同步、ETF 配置生成及看板读取。审查范围是整个代码库，下面记录本轮已经落实的修复；任务尚未宣告完成。

## 必须修复的问题：已落实

1. **ETF 配置仍写旧版策略分段**（`etf_selection/src/selection.py`）
   - 用途：把筛选篮子转为平台配置。
   - 问题：修改的是 `strategies.segments`，现行 `strategy.params.universe` 保留原篮子，导致资产与策略范围不一致。
   - 修复：直接更新现行单策略映射，移除旧结构生成；测试使用现行配置契约。
   - 不修复的后果：生成文件虽然存在，平台计算的却是旧投资范围。

2. **ETF 空结果导致二次崩溃**（`etf_selection/src/selection.py`）
   - 用途：报告候选拒绝原因与合格篮子。
   - 问题：全部候选缺失时访问不存在的 `history_years`；空排名或全部篮子历史不足时访问不存在的评分列。
   - 修复：在没有可评分对象时返回空结果，保留候选拒绝原因；移除生成阶段重复且硬编码的三年门槛。
   - 不修复的后果：用户看不到正常的“无合格候选”结果。

3. **ETF 筛选没有落实新鲜度与末日对齐检查**（`etf_selection/src/selection.py`、`etf_selection/scripts/screen_etf_sleeves.py`）
   - 用途：在筛选前确认行情可用。
   - 问题：过期或末日不同的有效候选仍可能参与评分。
   - 修复：拒绝过期、空行情及末日不同的数据；CLI 同步全部启用候选并复查，任何一步失败均停止。
   - 不修复的后果：筛选可能依赖过期或不可比较的数据快照。

4. **限定日期同步会删除已有行情**（`platform/src/platform_core/data_store.py`）
   - 用途：合并供应商返回的数据。
   - 问题：保护逻辑只看新数据首日；首日覆盖本地时，较晚行情及响应中缺失的中间日期可能被整表覆盖删除。
   - 修复：保留响应未包含的本地日期，只更新实际返回的日期。
   - 不修复的后果：历史同步可能破坏当前行情及既有长历史。

5. **快照与行情写入失败会破坏原文件**（`platform/src/platform_core/storage.py`、`data_store.py`）
   - 用途：保存账户、checkpoint、报告指标与行情。
   - 问题：直接以写模式打开目标文件；序列化或写入出错后，旧文件可能已被截断。
   - 修复：完整写入同目录唯一临时文件后再原子替换；失败时清理临时文件并保留原文件。JSON 拒绝非有限数。
   - 不修复的后果：单次失败可能丢失可恢复的账户状态。

6. **非有限数及重复持仓能够进入资金状态**（`models.py`、`execution.py`、`live.py`）
   - 用途：校验权重、费用、实际持仓、现金与申赎。
   - 问题：`NaN` 权重绕过比较；负费用、非法数量或成本、重复代码及非有限现金/申赎可能造成错误记账。
   - 修复：在输入边界拒绝非法值，并验证失败前后账户和净值文件保持一致。
   - 不修复的后果：产生无法解释的净值、错误持仓或被关闭的数值判断。

7. **已确认股息仍依赖源文件保留对应行**（`live_dividends.py`）
   - 用途：应收股息到期转为现金。
   - 问题：支付逻辑嵌在源 CSV 的循环内；漏行或文件暂时缺失后，应收可能长期不到账。
   - 修复：从已保存的应收独立结算，保留重启和重复执行的幂等性。
   - 不修复的后果：现金低估，后续订单按错误余额计算。

8. **不同股息因金额相同而被合并**（`live_dividends.py`）
   - 用途：分别确认独立登记事件的权益。
   - 问题：按资产、金额和支付日去重，可能只创建一份应收，支付时再查找已移除的项目。
   - 修复：事件键决定权益身份；老账户未关联应收只认领一次，不同事件分别记账。
   - 不修复的后果：权益少计或支付过程抛出 `StopIteration`。

9. **登记日权益忽略快照之后的成交**（`live_dividends.py`）
   - 用途：确定登记日收盘持有份额。
   - 问题：只要存在旧快照就完全忽略成交流水；快照后卖出 100 份仍可能按原 300 份分红。
   - 修复：从最近快照叠加至登记日的真实买卖与转入流水，并校验数量、股息为非负有限数。
   - 不修复的后果：少计或多计真实权益。

10. **模拟组合每日重启改变调仓节奏**（`engine.py`、`sim.py`、`data.py`、`strategies/macro_factor_es.py`）
    - 用途：让模拟组合从 checkpoint 连续推进。
    - 问题：运行状态未保存；截断日历把每天当月末；宏观因子平滑矩阵只在实例内保存；失效的内存版本号可导致恢复失败。
    - 修复：保存和恢复策略身份与运行状态；日历边界使用已知下一交易日或下一工作日；矩阵以列表持久化；失效版本号重新建立。
    - 不修复的后果：每日重启与批量运行得到不同订单意图。新增测试直接比较两种方式的最终状态。

11. **旧日出票及同日无操作留下错误票据**（`live.py`）
    - 用途：展示当前可执行的调仓票。
    - 问题：历史 `plan` 可以回退较新的运行状态；同日重新对账后无需交易，原订单 CSV 仍被看板读取。
    - 修复：拒绝使用较新账户状态生成历史票；同日变为无操作时移除原订单明细。
    - 不修复的后果：展示过时订单，后续状态恢复也可能沿用旧日状态。

12. **基本面文件路径、代码类型及异常处理不可靠**（`strategies/black_litterman_es.py`）
    - 用途：读取配置数据目录中的时点基本面视图。
    - 问题：路径固定到仓库；纯数字代码可能丢失前导零；文件损坏被全部吞掉并静默改为零观点。
    - 修复：在策略初始化时读取配置目录，明确以字符串读取代码并校验日期与数值；缺文件仍可中性处理，损坏文件明确失败。删除从未使用的债券收益率缓存及其加载过程。
    - 不修复的后果：基本面输入可能悄然失效，表面上仍正常出结果。

13. **固定权重策略忽略目标之外的旧仓**（`strategies/fixed_weight.py`）
    - 用途：将组合恢复到指定资产范围和权重。
    - 问题：只检查目标资产；已移出范围的 2% 旧仓可能一直保留。
    - 修复：同时检查当前持仓与目标集合，目标为零时也检查相对偏离；溢价闸门策略复用同一套阈值逻辑。
    - 不修复的后果：实际资产范围与配置长期不一致。

14. **看板对缺列与平坦序列处理错误**（`platform_dashboard/artifacts.py`）
    - 用途：聚合调仓事件并减少图表点数。
    - 问题：缺少 `trade_value` 时对标量调用 `fillna`；按值去重会把平坦序列末日删掉。
    - 修复：按行索引建立缺省金额序列；按位置采样且保留首末日期。
    - 不修复的后果：历史产物打不开，或图表误显示提前结束。

## 应当精简的问题：已落实

15. **无调用代码与重复实现增加维护成本**（跨模块）
    - 用途：原有数据接口、资产解析、运行环路与看板缓存。
    - 问题：存在无调用的查询/导入/指标写出/状态导出/缓存签名函数，三份相同资产解析、两份质量报告类型和重复的订单意图及分红处理。旧实验流水线还依赖失效的配置分段、硬编码 Python 路径及固定缓存失效日期。
    - 修复：删除确认无引用的函数和旧流水线；复用现有资产解析；订单意图归入组合状态；回测和模拟共用分红处理；统一 JSON 持久化并移除纯转发方法。九处月末字符串兼容分支改用 `pd.offsets.MonthEnd()`。
    - 不修复的后果：修复必须重复落地，调用方和实现更容易漂移。

16. **买入现金上限用逐手循环寻找**（`execution.py`）
    - 用途：在比例佣金和最低佣金下计算最大可买数量。
    - 问题：最低佣金高于可用现金时，会反复逐手减量；每次成交还重建同一份估值价格映射。
    - 修复：同时求解比例费与最低费的两个现金约束，直接向下取整；复用本次执行已经计算的估值价格。
    - 不修复的后果：异常费用配置或较大数量下产生不必要的循环和重复工作。

17. **企业行为同键冲突没有按文档报警**（`corporate_actions.py`）
    - 用途：保留本地已验证事件，提示人工核对上游差异。
    - 问题：旧值虽保留，但同键内容冲突被静默忽略。
    - 修复：比较共有的非键列并记录冲突；增量比较时拒绝重复上游键。
    - 不修复的后果：操作人员无法发现上游与本地事件不一致。
