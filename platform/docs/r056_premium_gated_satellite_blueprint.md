## 0. 课题定位

R039（行业动量）与 R049（行业估值）双双 Failed，R050 虽 Passed 但按
`core + w·satellite` vs `core` 的边际口径贡献为负——行业池与核心相关 0.763，
本质是核心里 510300 的高波动翻版，加进去同时降低收益、抬高波动、加深回撤。

卫星仓因此改用**与核心低相关**的跨市场标的（`513100` 与核心训练段相关 0.283）。
但前置审计发现 `513100` 的场内溢价是结构性的（QDII 额度稀缺，日频自相关 0.855），
当前 10.42% vs 历史中位 0.44%，直接建仓即预付一次性 -9.03%。

本课题因此问：

> **能否把"溢价高时不入场"变成一条纪律（而非预测），使跨市场卫星仓可用？**

## 1. 三臂预注册（运行前定型）

| 臂 | 配置 | 作用 |
|---|---|---|
| A 候选 | `r10_core_satellite_premium_gated.yaml` | 核心70%+纳指30% + 溢价闸门 |
| B 对照 | `r10_core_satellite_no_gate.yaml` | 同篮同权无闸门，**隔离闸门本身的贡献** |
| C 基线 | `r8_permanent_real_fixed_weight_threshold.yaml` | 纯核心，回答"该不该加卫星" |

三臂一次性全部跑完，不因中途结果增删臂。

## 2. 策略规格（A 臂）

`premium_gated_satellite`（`strategies/premium_gated_satellite.py`）：

- **目标权重**：核心 4 只组内等权、合计 70%（各 17.5%），卫星 `513100` 30%。
- **闸门**：可观测溢价 > `premium_cap` 时卫星目标权重置 0，
  其权重按核心**组内相对比例**回流核心（核心内部比例不变，各 25%）。
- **闸门重估**：`gate_eval=month_end`，非重估日沿用记忆状态；
  权重漂移仍由 5/25 带**每日**检查。慢信号慢评估、快漂移快纠正。
- **无信号即关闸**：卫星无净值数据、或历史不足以扣除发布滞后时，闸门默认关闭。
- 空仓建仓、触带整体归位等行为与 R038 一致，回测 / sim / live plan 三环路同构。

## 3. 冻结参数（首次运行前定型，全程无搜参）

| 参数 | 值 | 依据 |
|---|---|---|
| `premium_cap` | 0.02 | 申赎套利往返成本量级（QDII 申购费+汇兑+T+2 价格风险）。**机制推断，非回测挑选** |
| `publication_lag_days` | 2 | QDII 净值 T+1~T+2 披露，取上界最保守 |
| `gate_eval` | month_end | 溢价日频自相关 0.855，是慢变量 |
| `satellite_weight` | 0.30 | 卫星仓常规量级 |
| `abs_band` / `rel_band` | 0.05 / 0.25 | 逐字沿用 R038 |

## 4. 数据链与前视防护（本课题的硬责任）

`etf_premium.py` 与 R049 的 `index_valuation.py` **不同构**，差异必须显式处理：

| | 行业指数估值（R049） | QDII 基金净值（R056） |
|---|---|---|
| 发布时点 | 当日（收盘价+已披露财报算出） | **T+1 ~ T+2**（需标的市场收盘与汇率结算） |
| 前视处理 | T 日信号 → T+1 执行即可 | **必须扣除发布滞后** |

三条实现约定（测试逐条断言）：

1. 滞后按**交易日**计数，不按自然日——否则长假后滞后会被动放松。
2. 价格与净值取**同一天**配对——用 `价格_T / 净值_{T-2}` 会把 2 天价格波动伪装成溢价波动。
3. 价格取**未复权原价**——复权价与净值不同基准，配对得到无意义的数字。

数据源两个坑（`scripts/fetch_etf_nav.py` 内已处理）：东财 lsjz 单页上限 20 条，
按 `len(data) < pageSize` 判停会静默截断到 20 行并"成功"返回；
`akshare.fund_etf_fund_info_em()` 在 1.18.64 上有列数 bug。

## 5. 败因（as-built 诊断，不用于调参）

**`premium_cap=0.02` 恰好落在溢价分布的众数区。** 训练段 78 个月末评估点：

| 区间 | 月份数 |
|---|---:|
| (-10%, 0%] | 20 |
| (0%, 1%] | 17 |
| **(1%, 2%]** | **10** |
| **(2%, 3%]** | **12** |
| (3%, 5%] | 9 |
| (5%, +∞) | 10 |

22 个月骑在阈值 ±1pp 内。二值闸门 + 骑线分布 = 必然 whipsaw，**78 个月翻转 26 次**，
26×5 笔 ≈ 130，与实测 146 笔吻合。`gate_eval=month_end` 的降频意图无效——
溢价的穿越本身就是月度尺度。

回撤恶化 3.29pp 指向同一机制：溢价常在市场承压时收窄，闸门此时开闸买入卫星＝
下跌途中加仓；反弹时溢价扩张又被切出。**信号有信息（Sharpe 35/39 起点改善），载体错了。**

⚠️ **本节的分布诊断不得用于挑一个新的 `premium_cap`**——那属于 post-hoc tuning，
`AGENTS.md` 明确禁止。若复研必须重新预注册设计。

## 6. 结论沉淀

**溢价是一次性的入场成本问题，不是需要持续择时的信号。**
用策略反复择时它，换手代价（14.5×）远超收益。正确处理是把它移出策略：
建仓那一刻人工检查一次溢价，高就等、低就按固定权重建仓，此后不再看。
这是一次性执行决策，不属于策略算法。
